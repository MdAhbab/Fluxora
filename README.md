# Fluxora

![Fluxora animated project banner](docs/fluxora-banner.svg)

Fluxora is a building management SaaS platform created by **Ahbab**. It brings apartment finance, visitor security, maintenance, resident communication, documents, bookings, parking, assets, and building analytics into one operating dashboard.

## What Fluxora Includes

| Area | Capabilities |
| --- | --- |
| Finance | Invoices, payments, monthly service charges, utility bills, expenses, and reporting |
| Security | Visitor QR scans, intercom logs, gate events, SOS incidents, lift status, and emergency contacts |
| Resident Operations | Notice board, resident directory, polls, documents, events, and group chat |
| Facilities | Shared resource bookings, units and occupancy, parking layout, vehicles, access cards |
| Maintenance | Tickets, staff attendance, assets, warranties, vendor lookup, and service provider reviews |

## Role-scoped experience

The dashboard renders a distinct module set per stakeholder, driven by `frontend/src/lib/roles.ts`:

| Role | Modules |
| --- | --- |
| Building Admin | Command · Finance · Operations · Security · Community · Real Estate |
| Committee | Boardroom · Approvals · Finance · Community · Estate |
| Resident | My Residence · Billing · Services · Visitors · Community · Marketplace |
| Gate Officer | Gatehouse · Expected · Gate Logs · Incidents |
| Staff | My Tasks · Attendance · Payroll · Noticeboard |

## Intelligence surfaces

The following surfaces ship in the UI today; the AI calls behind them route through a provider gateway specified in [AGENTS.md](AGENTS.md) (self-hosted **Gemma**, user-supplied keys with multi-key fallback, or **Fluxora Managed AI**). Until that backend gateway lands, these surfaces operate as manual/progressive-enhancement paths:

| Feature | Description |
| --- | --- |
| 3D Building Explorer | Procedural model of the building built from live unit data — hover/click any flat to see its residents and status. |
| Flux Concierge | Floating assistant for residents and admins: check balances, book facilities, create visitor passes, and file tickets in natural language. |
| Triage Desk | Maintenance triage — incoming tickets auto-categorized, prioritized, and matched to the best staff member as proposals a human approves. |
| Building Pulse | Monthly editorial digest for committees: collections, expense anomalies, maintenance hot-spots, and recommended actions, rendered as a print-style report. |
| Notice Scribe | Bilingual notice composer — drafts from a one-line brief with tone presets and publishes paired Bangla ⇄ English notices. |

## Tech Stack

- **Frontend:** React 18, TypeScript, Vite 6, Tailwind CSS v4, shadcn/ui, React Router 7, Motion
- **Backend:** Django, Django REST Framework, token authentication
- **Database:** MySQL
- **Optional services:** Celery, Redis, Channels, S3 storage, email/SMS providers

## Project Structure

```text
backend/
  fluxora/            # Main Django app: models, views, URLs, seed command
  fluxora_saas/       # Django project settings/ASGI/WSGI/Celery package
  manage.py
frontend/
  src/
    app/              # Pages, role modules, shared + shadcn/ui components
    lib/
      api.ts          # Token-auth REST client for the Django backend
      auth.tsx        # Real login/signup + offline demo fallback
      data.tsx        # DataProvider — fetches /api/dashboard/summary, exposes useData()
      adapt.ts        # Maps backend rows into the UI's view models
      mock.ts         # Demo data used as the offline fallback
      roles.ts        # Per-role module map
docs/
  fluxora-banner.svg  # GitHub-compatible animated README banner
```

`backend/staticfiles/` is generated by Django `collectstatic` and is intentionally not committed.

## Frontend ↔ backend wiring

The frontend authenticates against `POST /api/auth/login` (token auth) and hydrates a single
`GET /api/dashboard/summary/?building_id=…` call into every module via `useData()`. Writes —
paying invoices, recording expenses, publishing notices, voting in polls, scanning visitors,
advancing tickets, booking facilities, staff check-in — call their REST endpoints and refresh.

If the backend is unreachable or a demo account signs in offline, the same selectors fall back
to bundled demo data so the interface always renders. The five building roles map 1:1 to backend
roles; the **Software Operations** console and the AI surfaces are client-side and await the
backend ops/AI gateway.

## Setup

### 1. Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install django djangorestframework mysqlclient celery channels
```

Set MySQL environment variables if your local values differ:

```bash
export MYSQL_DATABASE=fluxora
export MYSQL_USER=root
export MYSQL_PASSWORD=12345678
export MYSQL_HOST=127.0.0.1
export MYSQL_PORT=3306
```

Run migrations and seed the Bangladeshi demo workspace:

```bash
python manage.py migrate
python manage.py seed_demo_data
python manage.py runserver 127.0.0.1:8000
```

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Open:

```text
http://127.0.0.1:5173/
```

The Vite dev server proxies `/api` requests to `http://127.0.0.1:8000`.

## Notes

- Run `seed_demo_data` any time you need fresh demo content. It is idempotent and updates existing demo records.
- The dashboard uses live Django API data through token authentication.
- Signup creates a new Fluxora workspace and stores selected modules, including Units & Occupancy, Assets & Compliance, and Parking & Access.
